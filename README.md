# 엔트리 로컬 (EntryLocal) — Windows exe + Android apk

공식 엔트리 오프라인(entry-offline v2.1.36, 커밋 `db7928d9`)을 포크해 **서버와 통신하지 않고**
**작품을 기기 내부 저장소에 보관**하도록 바꾼 엔트리입니다. 같은 패치(`entry-local.patch`)로
Windows 프로그램(exe)과 안드로이드 앱(apk)을 모두 만듭니다.

선택 기능으로 **구글 드라이브 연동**을 넣을 수 있습니다. 빌드할 때 구글 클라이언트 ID 를 넣은 경우에만 켜지고,
넣지 않으면 로그인 버튼조차 없는 순수 오프라인 앱이 됩니다 (아래 C 참고).

## 두 판의 공통 동작

| 구분 | 원본 엔트리 오프라인 | 엔트리 로컬 (exe / apk 공통) |
|---|---|---|
| 저장하기 | 매번 파일 저장 창 | 내부 저장소에 바로 저장 (처음엔 새 작품, 이후 덮어쓰기) |
| 다른 이름으로 저장 | 파일 저장 창 | `○○ 복사본` 으로 새 작품 생성 |
| 자동 저장 | 비정상 종료 복구용 임시본만 | 임시본 + 저장된 작품은 바뀐 내용이 있으면 1분마다 저장 (실행 중엔 건너뜀) |
| 불러오기 | 파일 열기 창 | **내 작품** 목록 (썸네일·검색·이름 바꾸기·복사·삭제·내보내기) |
| 파일 주고받기 | — | `파일로 내보내기 (.ent)`, `파일에서 가져오기 (.ent)` |
| 공유·실시간 변수/리스트 | 서버 저장·동기화 | 불러올 때 일반 변수로 변환, 만들기 메뉴에서 선택지 숨김 |
| 신호 | 엔진 내부 | 그대로 (원래 로컬 동작) |
| 업데이트 확인·하드웨어 로그·원격 모듈 | playentry.org 접속 | 하지 않음 |
| 하드웨어 연결 | hw.playentry.org 중계 먼저 시도 | 이 PC(127.0.0.1)만 (apk 는 하드웨어 기능 없음) |

`.ent` 형식은 공식 엔트리와 같습니다. 서로 만든 파일을 주고받아 열 수 있습니다 (아래 검증 참고).

## 성능 (3D·무거운 작품용)

상단 **성능** 메뉴에서 켜고 끕니다. 설정은 기기에 저장됩니다.

| 설정 | 기본 | 하는 일 | 언제 |
|---|---|---|---|
| **엔진 최적화** | 켜짐 | 엔트리 블록 해석기의 병목 4곳을 고침. **계산 결과·화면은 원본과 동일** | 항상 (문제 생기면 끄고 비교) |
| **부스트 모드** | 켜짐 | 무대를 GPU(WebGL)로 그림. 엔트리 공식 '부스트 모드'와 같은 기능 | 복제본·붓·채우기를 많이 쓰는 작품 |
| **터보 모드** | 꺼짐 | 한 프레임 시간 안에 블록을 여러 번 실행 (Scratch 터보 모드 방식) | **반복 블록**으로 계산하는 작품. 함수 재귀로 한 틱에 다 그리는 작품(엔트리 둠 등)은 효과 없음 |

엔진 최적화 내용 (`src/renderer/helper/entry/engineBoost.ts`, `fastMath.ts`):
1. 변수·리스트 찾기: 매번 lodash 로 전체 목록(100개 이상)을 훑던 것을 위치 기억으로
2. 사칙연산: 매 연산 BigNumber 객체 생성 → 정수·보장 범위는 일반 연산, 나머지는 BigInt 로 같은 십진 계산
   (나눗셈은 BigNumber 기본 설정과 같은 소수 20자리 반올림). 결과 0 은 부호 규칙 때문에 원래 경로.
   엔트리에 들어 있는 bignumber.js 와 무작위 400만 건 비교 — 불일치 0 (+0/−0 까지 엄격 비교)
3. 함수 호출: 매번 지역변수 cloneDeep → 값이 단순하면 얕은 복사
4. 블록 값 계산: 클로저 할당을 반복문으로

측정 — **엔트리 둠: 하역 기지** (함수 12개, 블록 812개):
- 같은 키 입력 400틱 플레이: 블록 실행 **틱당 33.4ms → 17.3ms (1.9배)**
- 원본 엔진과 최적화 엔진의 결과 비교: 변수 54개, 리스트 56개(항목 11,171개), 오브젝트 8개,
  중간 상태 8회, **무대 화면 픽셀까지 모두 동일**
- 터보 모드: 이 작품은 한 틱이 이미 16ms 를 넘어 효과도 부작용도 없음 (14.1 / 14.0 fps)
- Windows판(Electron)에서 34fps, 오류 없음
- 부스트 모드의 GPU 효과는 GPU 가 없는 측정 서버에서는 확인 불가 — 실제 기기에서 비교 필요

## 저장 위치

- **Windows**: `%APPDATA%\EntryLocal\projects\` — 작품마다 `<id>.ent`, 목록은 `index.json`
- **Android**: 앱 전용 내부 저장소 `/data/data/biz.softline.entrylocal/files/projects/` (다른 앱에서 접근 불가)
  - 내보내기를 누르면 안드로이드 공유 창이 떠서 드라이브·파일 앱·메신저 등으로 보낼 수 있습니다.
  - 앱을 삭제하면 작품도 함께 지워집니다. 중요한 작품은 내보내기로 백업하세요.

## 구글 드라이브 연동 (선택 기능)

인터넷이 연결되어 있으면 상단에 **로그인** 버튼이 나타납니다 (끊기면 숨김).

- **로그인**: 구글 로그인 창 → 허용하면 원래 화면으로 돌아오고, 버튼 자리에 계정 이름이 표시됩니다.
  - Windows: 기본 브라우저에서 로그인 → 앱으로 자동 복귀. 한 번 로그인하면 앱을 다시 켜도 유지
    (토큰은 Windows 자격 증명 보호로 암호화해 `%APPDATA%\EntryLocal\google-account.dat` 에 저장).
  - Android: 기기에 등록된 구글 계정을 고르는 시스템 창.
- **저장 메뉴**: `이 기기에 저장` / `구글 드라이브에 저장` 으로 나뉩니다. 그냥 `저장하기`(Ctrl+S)는 마지막에 저장한 곳에 덮어씁니다.
- **내 작품**: `이 기기` / `구글 드라이브` 탭. 드라이브 탭에서 열기·이름 바꾸기·내보내기·삭제(드라이브 휴지통으로, 30일 안에 복구 가능).
- 작품은 내 드라이브의 **`엔트리 로컬` 폴더**에 `.ent` 파일로 저장됩니다. 구글 드라이브 웹에서 내려받아 다른 엔트리에서도 열 수 있습니다.
- 권한은 `drive.file` 만 요청합니다 — **이 앱이 만든 파일만** 볼 수 있고, 드라이브의 다른 파일은 볼 수 없습니다.
- 자동 저장(1분)은 이 기기에 저장된 작품에만 동작합니다. 드라이브 작품은 저장을 누를 때만 올라갑니다.
- 계정 메뉴 → 로그아웃 시 이 기기의 로그인 정보가 지워집니다 (Windows판은 구글 쪽 권한도 해제).

참고: 엔트리 공식 사이트(playentry.org) 계정 연동은 공개 API 가 없어 넣지 않았습니다. 앱이 엔트리 비밀번호를 받는 방식은 보안상 쓰지 않습니다.

## A. Windows exe 빌드

필요: Git, Node.js 20 LTS 이상, Python 3, Visual Studio Build Tools(C++ 데스크톱 개발)

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build-windows.ps1
```

결과: `entry-offline\dist\EntryLocal-win32-x64\EntryLocal-Setup-2.1.36.exe`, `EntryLocal-Portable-2.1.36.exe`

## B-1. Android apk — GitHub 에서 빌드 (PC 설치 없음, 추천)

1. GitHub 에서 새 저장소를 만듭니다 (**Private** 권장).
2. 이 키트 폴더의 파일을 **숨김 폴더 `.github` 까지 포함해** 그대로 올립니다.
   - 웹에서 올릴 때: 저장소 → Add file → Upload files 에 폴더째 끌어다 놓기
3. (권장) 서명 키 등록: Settings → Secrets and variables → Actions → New repository secret
   - `ENTRY_KEYSTORE_PASSWORD`, `ENTRY_KEYSTORE_BASE64` (값은 `서명키_보관용.txt` 참고)
   - 등록하면 매번 같은 키로 서명되어, 새로 빌드한 APK 를 기존 앱 위에 **작품을 유지한 채 업데이트** 설치할 수 있습니다.
   - 등록하지 않으면 빌드마다 임시 키로 서명됩니다 (업데이트 시 기존 앱을 지우고 다시 설치해야 함).
4. Actions 탭 → **APK 빌드** → **Run workflow**
5. 20~40분 뒤 완료되면 실행 기록을 눌러 아래 **Artifacts → EntryLocal-apk** 를 내려받습니다 (zip 안에 apk).

## B-2. Android apk — 내 PC 에서 빌드

필요: Git, **Node.js 22 이상**, **Android Studio** (설치 후 한 번 실행해서 SDK 설치 — SDK Platform 36 포함).
JDK 는 Android Studio 에 들어 있는 것을 자동으로 찾습니다.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build-android.ps1            # 바로 설치해서 쓸 APK (디버그 서명)
.\build-android.ps1 -Release   # 배포용 APK (처음 한 번 서명 키 비밀번호를 물어봄)
```

Linux/macOS: `./build-android.sh` / `./build-android.sh --release`

결과: `out\EntryLocal-2.1.36-debug.apk` (약 600MB — 라이브러리 그림·소리 포함)

처음 빌드는 Gradle·안드로이드 라이브러리를 내려받느라 시간이 꽤 걸릴 수 있습니다.

### 태블릿에 설치

1. APK 를 태블릿으로 옮깁니다 (USB, 드라이브, 메신저 등).
2. 파일을 누르면 "출처를 알 수 없는 앱 설치" 허용을 묻습니다 → 허용 후 설치.
3. 또는 PC 에서 `adb install out\EntryLocal-2.1.36-debug.apk`

- 가로 화면 고정입니다. **10인치 이상 태블릿**을 권장합니다 (휴대폰은 화면이 축소되어 표시됨).
- 블록은 손가락으로 끌어서 놓을 수 있습니다.
- 뒤로가기 버튼: 열린 '내 작품' 창을 닫고, 없으면 종료 확인을 묻습니다.
- 배포용 서명 키(`entry-offline\mobile\android\entrylocal.jks`)와 비밀번호는 잃어버리면 같은 앱으로 업데이트할 수 없으니 따로 보관하세요.

### 안드로이드판 구조

Electron 대신 Capacitor(안드로이드 WebView)로 같은 엔트리 화면을 띄웁니다.
화면·저장·내 작품 코드는 exe 와 같은 소스를 쓰고, Electron 이 하던 일만 브라우저용으로 다시 만들었습니다.

| Electron 판 | 안드로이드판 (`src/web/`) |
|---|---|
| preload (window.ipcInvoke 등) | `shim.ts` |
| main 프로세스 (저장·가져오기·내 작품 등 IPC 29개) | `webMain.ts` |
| userData 폴더 | `vfs.ts` — Capacitor Filesystem(앱 내부) / PC 확인용 개발 서버 |
| node-tar (.ent/.eo) | `tar.ts` — 같은 tar.gz 형식 직접 읽고 쓰기 |
| nativeImage·ffmpeg | `media.ts` — 캔버스 리사이즈, mp3 인코딩(lamejs) |
| 파일 대화상자 | `platform.ts` — 파일 선택기 / 공유 창 |

PC 브라우저로 안드로이드판 화면을 미리 보려면:
```bash
cd entry-offline && yarn build:web
cd mobile && npm ci && node scripts/assemble-www.js && node scripts/dev-server.js
# http://localhost:8100/
```

## C. 구글 드라이브 연동 설정 (선택, 처음 한 번)

구글 클라우드에 '이 앱' 을 등록해 클라이언트 ID 를 받는 과정입니다. 무료이고 15분 정도 걸립니다.
`drive.file` 은 구글이 **민감하지 않은 권한**으로 분류하므로 앱 심사가 필요 없습니다.

### 1) 프로젝트와 API
1. https://console.cloud.google.com 에 로그인 → 상단 프로젝트 선택 → **새 프로젝트** (이름 예: `entry-local`)
2. **API 및 서비스 → 라이브러리** → `Google Drive API` 검색 → **사용**

### 2) 동의 화면 (Google 인증 플랫폼)
1. **API 및 서비스 → OAuth 동의 화면** (또는 *Google 인증 플랫폼*) → 시작하기
2. 앱 이름(예: `엔트리 로컬`), 지원 이메일 입력 → 대상: **외부** → 완료
3. **데이터 액세스 → 범위 추가**: `.../auth/drive.file`, `openid`, `email`, `profile`
4. **대상(Audience)**
   - 처음엔 *테스트* 상태 — **테스트 사용자**에 로그인할 계정(학생 계정 포함, 최대 100개)을 추가해야 로그인됩니다.
     테스트 상태에서는 **7일마다 로그인이 풀립니다.**
   - 잘 되는 것을 확인했으면 **앱 게시(프로덕션으로 푸시)** → 누구나 로그인, 7일 제한 없음.
     민감하지 않은 권한만 쓰므로 심사 없이 바로 게시됩니다 (로그인 창에 '확인되지 않은 앱' 경고가 나오면 고급 → 계속).

### 3) 클라이언트 3개 만들기 (**클라이언트 → 클라이언트 만들기**)

| 종류 | 입력 | 받는 값 | 쓰는 곳 |
|---|---|---|---|
| **데스크톱 앱** | 이름만 | 클라이언트 ID, **보안 비밀** | Windows exe |
| **웹 애플리케이션** | 이름만 (브라우저 미리보기도 쓰려면 승인된 JavaScript 원본 `http://localhost:8100`, 리디렉션 URI `http://localhost:8100/oauth-callback.html`) | 클라이언트 ID | Android apk (아래 Android 클라이언트와 짝) |
| **Android** | 패키지 이름 `biz.softline.entrylocal`, SHA-1 `0C:D2:02:FA:E3:53:AF:36:E7:40:3F:91:D6:F5:32:59:EE:FE:A9:B9` | (값은 안 씀 — 만들어 두기만) | Android apk |

- Android 클라이언트의 SHA-1 은 **서명 키의 지문**입니다. 위 값은 함께 드린 `entrylocal.jks` 의 것입니다.
  GitHub Secrets 에 이 키를 등록해 빌드한 APK 에서만 로그인됩니다.
  - 내 PC 에서 디버그 빌드(`build-android.ps1`)로 시험하려면 디버그 키의 SHA-1 로 Android 클라이언트를 **하나 더** 만드세요:
    `keytool -list -v -keystore %USERPROFILE%\.android\debug.keystore -alias androiddebugkey -storepass android`
  - 키가 달라지면 로그인 시 '개발자 콘솔 설정 오류' 같은 메시지가 납니다.
- 데스크톱 앱의 보안 비밀은 설치형 앱 특성상 프로그램에 들어갑니다 (구글 문서상 설치형 앱의 비밀은 비밀로 취급되지 않음).
  로그인은 PKCE 로 보호됩니다.

### 4) 빌드에 넣기
- **GitHub Actions (APK)**: 저장소 Settings → Secrets and variables → Actions → New repository secret
  - 이름 `GOOGLE_WEB_CLIENT_ID`, 값: 웹 애플리케이션 클라이언트 ID (`....apps.googleusercontent.com`)
  - 그 뒤 Run workflow 로 다시 빌드. (워크플로 파일 `.github/workflows/build-apk.yml` 도 새 것으로 바꿔 올려야 합니다)
- **내 PC 빌드 (exe·apk)**: 키트 폴더의 `google-client.example.json` 을 복사해 `google-client.json` 으로 이름을 바꾸고 값을 채운 뒤
  `build-windows.ps1` / `build-android.ps1` 실행. (이 파일은 `.gitignore` 에 있어 GitHub 에 올라가지 않습니다)
- 값을 비우고 빌드하면 연동 기능이 빠진 앱이 됩니다.

## D. 앱 이름·아이콘 바꾸기 (안드로이드)

키트의 `branding` 폴더에 파일을 넣고 다시 빌드하면 됩니다.

| 파일 | 내용 |
|---|---|
| `app-name.txt` | 홈 화면 이름 한 줄. 한글 7~8자 이내 권장 (길면 홈 화면에서 잘림) |
| `icon.png` | 정사각형 PNG, 512×512 이상 (1024×1024 권장). 투명 배경 가능 |
| `icon-bg.txt` | (선택) 배경색 `#RRGGBB`. 없으면 아이콘 왼쪽 위 모서리 색 |

- 빌드 때 `icon.png` 하나로 런처 아이콘 15개(해상도 5단계 × 사각·원·적응형)와 시작 화면 11개를 만듭니다.
- 안드로이드 8 이상은 런처가 아이콘을 원·물방울 등 모양으로 잘라 씁니다. **중요한 그림은 가운데 2/3 안에** 두세요.
- GitHub 빌드: `branding` 폴더째 저장소에 올리고 Run workflow.
- 패키지 ID(`biz.softline.entrylocal`)는 바뀌지 않습니다 → 기존 앱 위에 업데이트 설치되고 작품·구글 로그인 설정도 그대로입니다.
  이름이 바뀐 앱을 설치해도 태블릿에 아이콘이 두 개 생기지 않습니다. (일부 런처는 재부팅 전까지 예전 아이콘을 보여 줄 수 있음)

## 알아둘 점

- **인터넷이 필요한 블록은 남아 있습니다.** 인공지능(번역·읽어주기·음성인식 등)·확장 블록(날씨 등)은 서버를 호출하므로
  오프라인에서는 동작하지 않습니다.
- 오브젝트·모양·소리 기본 리소스는 앱에 모두 내장되어 있어 인터넷 없이 추가할 수 있습니다 (APK 가 큰 이유).
- 안드로이드판에서 안 되는 것: 하드웨어 연결, 아주 오래된 XML 형식 작품 열기(PC판에서 한 번 저장하면 열림).
- 공식 엔트리 오프라인은 MIT 라이선스입니다. 외부 배포 시 '엔트리' 명칭·로고는 네이버 커넥트재단 소유이므로
  이름과 아이콘을 바꾸는 것을 권합니다. (안드로이드판 아이콘은 자체 제작한 블록 모양입니다.)

## 검증한 내용

이 작업 환경에서는 Android SDK·Gradle 저장소가 막혀 있어 **APK 파일 자체는 빌드하지 못했습니다.**
대신 아래를 실제로 실행해 확인했습니다.

**Windows(Electron)판** — Linux + Xvfb 에서 실행
- 저장 / 덮어쓰기 / 다른 이름으로 저장 / 내 작품 목록 / 다시 열기, 변수 로컬화
- 하드웨어 소켓은 127.0.0.1 에만 접속, 외부 요청 0건

**안드로이드판 화면** — 새로 받은 원본에 패치를 적용하고 빌드 스크립트를 Gradle 직전까지 실행해서 만든 앱 자산을
Chromium 141 에 띄워 확인 (Gradle 이후는 표준 Capacitor 빌드)
- 저장 → 내부 저장소, 덮어쓰기, 복사본, 내 작품 목록(2개), 다시 열기 후 그림 5개 모두 표시·소리 재생
- 라이브러리 그림(png·svg)·직접 올린 jpg(→png 변환)·라이브러리 소리 추가, 소리 라이브러리 1,420개 경로 전부 확인
- 그림판 저장, 소리 편집기 저장(mp3 인코딩)
- `.ent` 내보내기 → Python tarfile 로 열림 → **Windows판에서 열기 성공**(그림 5개 표시)
- **Windows판에서 만든 `.ent` → 안드로이드판에서 열기 성공**
- 터치 에뮬레이션으로 블록 끌어 놓기 성공
- 하드웨어 카테고리 숨김, 외부 요청·웹소켓 0건

**구글 드라이브 연동** — 구글 서버를 흉내 내는 시험 서버(`scripts/mock-google.js`, 실제 OAuth·Drive API v3 형식)로 확인
- 브라우저(안드로이드판 화면): 오프라인이면 로그인 버튼 숨김 → 팝업 로그인 후 원래 화면 복귀·계정 이름 표시 →
  드라이브에 저장(폴더 자동 생성·썸네일) → 다시 저장은 덮어쓰기(파일 1개), 다른 이름으로 저장은 새 파일 →
  드라이브 탭 목록·썸네일·이름 바꾸기·열기(변수 값 복원)·휴지통 삭제 → 로그인 만료 시 다시 로그인 안내 → 로그아웃 후 드라이브 메뉴 숨김. 오류 0건
- Windows판(Electron): 브라우저 로그인(루프백+PKCE) → 드라이브 저장 → 토큰 만료 후 자동 갱신 → 열기 →
  **앱 재시작 후에도 로그인 유지** → 로그아웃 시 토큰 해제
- 확인 못 한 것: **실제 구글 계정 로그인**과 **안드로이드 시스템 계정 선택 창**(이 환경에서 구글 접속이 막혀 있음).
  설정 후 실제 기기에서 로그인 → 드라이브 저장 → 구글 드라이브 웹에서 `엔트리 로컬` 폴더 확인 순서로 시험해 주세요.
- 이 과정에서 찾아 고친 버그: '내 작품' 창이 열려 있을 때 삭제 확인 창이 그 뒤에 가려지던 문제 (이 기기 탭에도 있던 문제)

설치 후 실제 태블릿에서 한 번 확인할 것: 저장 → 앱 종료 → 다시 실행 → 내 작품에서 열기, 내보내기(공유 창), 소리 재생.
